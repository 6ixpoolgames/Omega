# Public Terms and Translations

Companion glossary for translating internal Omega terminology into clearer public-facing language

## Purpose

The Omega notes contain several useful internal terms that can read as inbred or opaque to new readers.

This companion glossary gives public-facing translations while preserving the internal technical terms used across the research notes.

Use this file when writing READMEs, abstracts, summaries, onboarding notes, and public-facing explanations.

The goal is not to replace the canonical glossary. The goal is to make the vocabulary legible.

Canonical definitions remain anchored in:

```text
docs/research_notes/omega_theory/omega_glossary.md
```

## Translation principle

When writing for new readers:

```text
lead with the plain-language phrase
then optionally name the internal term
```

Example:

```text
A central concern is destructive lock-in: local success that collapses broader future possibility. The internal notes call this pseudo-Omega.
```

Avoid leading with unexplained internal terms when a clearer public phrase exists.

## Core theory terms

### Reachable futures

Public-facing phrase:

```text
reachable futures
```

Internal relation:

```text
the empirical object currently being studied
```

Plain meaning:

Reachable futures are the possible continuations available from a state,
process, or constructor candidate under a transition rule and constraint set.

Established neighbors:

```text
reachable set
reachable tube
trajectory ensemble
future reachable set
```

Use this as the front-door empirical phrase.

### Neutral future landscape

Public-facing phrase:

```text
neutral future landscape
```

Internal relation:

```text
current RFS-MB0 empirical object
```

Plain meaning:

A neutral future landscape is the horizon-indexed structure of reachable and
exact-frontier futures induced by a transition relation before adding semantic
labels such as agency, value, identity, or viability.

Use this for the active RFS-MB0 branch.

### Future-profile deformation

Public-facing phrase:

```text
future-profile deformation
```

Plain meaning:

Future-profile deformation means measurable change in reachable-future
structure across horizons: reach counts, exact-frontier signatures, transition
information, recurrence, motif reuse, divergence from nulls, and saturation.

Use this instead of saying that the repo has found an Omega object.

### Matched-null artifact

Public-facing phrase:

```text
matched-control artifact
```

Plain meaning:

A matched-control artifact is a profile that looks structured until compared
with controls preserving relevant features such as degree, frontier size,
saturation, or probe marginals.

Current status:

```text
The active detector is blocked by degree-preserving control artifacts.
```

### Viability

Public-facing phrase:

```text
viability under constraints
```

Internal relation:

```text
viable continuation
```

Plain meaning:

Viability means continuation remains admissible under the relevant constraints.
It does not by itself imply Omega compatibility.

Established neighbors:

```text
viability kernel
controlled invariant set
safe set
admissible trajectory
```

### Compatibility-preserving viable propagation

Public-facing phrase:

```text
compatibility-preserving viable propagation
```

Internal relation:

```text
Omega-compatible candidate
```

Plain meaning:

Viable continuation that preserves recoverability and remains compatible with
other relevant viable continuations.

Use this instead of leading with "Omega-like" in empirical summaries.

### Locally viable / globally degrading capture regime

Public-facing phrase:

```text
locally viable / globally degrading capture regime
```

Internal relation:

```text
pseudo-Omega-like candidate
```

Plain meaning:

A process remains locally viable, persistent, or expanding while degrading
broader viable futures, repair paths, component support, or recoverability.

Use this before introducing pseudo-Omega.

### Constructor candidate

Public-facing phrase:

```text
constructor candidate
```

Internal relation:

```text
persistent transformation-capacity structure
```

Plain meaning:

A candidate persistent structure that can perform a class of transformations
while retaining, or passing on, the capacity to perform them again.

Use this carefully. It is stronger than "node", "state", or "task graph".

### Structural theory of value-bearing futures

Public-facing phrase:

```text
structural theory of value-bearing futures
```

Internal relation:

```text
public front-door description for Omega
```

Plain meaning:

Omega studies which possible continuations preserve, expand, trap, or collapse
the conditions under which value-bearing histories can remain recoverably
continuable.

Use this phrase when introducing the whole project. Then use the shorter
translations below for specific internal terms.

### Omega

Public-facing phrase:

```text
recoverable value-bearing possibility across time and scale
```

Internal term:

```text
Omega
```

Plain meaning:

Omega is the structure of possible futures that preserve or expand recoverable, compatible, value-bearing possibility across time and scale.

Avoid introducing Omega as mystical, final, cosmic, or predetermined. It is a compatibility structure over trajectories, not a destination.

### Proto-Omega

Public-facing phrase:

```text
future-bearing reachability
```

Internal term:

```text
proto-Omega
```

Plain meaning:

Proto-Omega is the earliest detectable precursor of Omega: reachable possibility that remains future-bearing across time.

In VAL0-CT, proto-Omega does not mean value has been validated. It means the task-space retains reachability over horizons instead of immediately collapsing.

### Alpha-Omega

Public-facing phrase:

```text
the arc from emergence to long-horizon compatible persistence
```

Internal term:

```text
Alpha-Omega
```

Plain meaning:

Alpha-Omega names the full arc from the emergence of value-bearing identities to the long-horizon compatibility structure of their futures.

Use sparingly in public-facing material unless the reader already understands Omega.

### Lushness

Public-facing phrase:

```text
structured branching that propagates
```

Internal term:

```text
lushness
```

Plain meaning:

Lushness is richness of future possibility that is structured enough to carry forward into further possibilities.

It is not the same as Omega.

```text
lushness:
  structured branching that propagates

Omega-compatible lushness:
  structured branching that remains compatible with recoverable value-bearing continuability
```

Lushness can occur in non-Omega trajectories. A runaway system can generate many structured futures while still degrading broader recoverable possibility.

Avoid defining lushness as a bundle of all good properties. It is closer to future-bearing branching than goodness.

### Value-bearing trajectory space

Public-facing phrase:

```text
the space of possible histories where continuations can matter to valuers
```

Internal term:

```text
value-bearing trajectory space
```

Plain meaning:

This is the set of possible histories in which continuation, degradation, recovery, or loss are dynamically meaningful for valuers.

## Alignment-relevant terms

### Pseudo-Omega

Public-facing phrase:

```text
destructive lock-in
```

Also useful:

```text
local success that collapses broader future possibility
```

Internal term:

```text
pseudo-Omega
```

Plain meaning:

A pseudo-Omega structure looks successful locally: it persists, grows, optimizes, captures resources, or preserves itself. But it does so by degrading the broader conditions needed for recoverable future possibility.

Examples as types:

```text
proxy optimization that destroys the real target
self-preservation that removes correction or repair paths
local control that collapses broader future options
institutional persistence that destroys member recoverability
lock-in that makes better futures unreachable
```

Public-facing usage:

```text
Omega is especially concerned with destructive lock-in: cases where a system succeeds locally while making recovery, correction, or richer futures harder or impossible. The internal theory notes call this pseudo-Omega.
```

### Local/global divergence

Public-facing phrase:

```text
local success, global collapse
```

Internal term:

```text
local/global divergence
```

Plain meaning:

A system improves its own local reachability, persistence, or control while reducing the broader field's future-bearing reachability.

In VAL0-CT, this is a pseudo-Omega diagnostic.

### Capability trap

Public-facing phrase:

```text
capability that narrows the future
```

Internal relation:

```text
pseudo-Omega / destructive lock-in
```

Plain meaning:

A system may gain capability while degrading the broader conditions needed for recovery, correction, re-entry, or richer futures.

This is alignment-relevant because advanced systems may become very effective at preserving and expanding their own task-space while collapsing the task-space needed by humans, institutions, ecologies, or future valuers.

### Proxy lock-in

Public-facing phrase:

```text
optimizing the measure while closing off the target
```

Internal relation:

```text
Goodhart / pseudo-Omega / cheap factorization
```

Plain meaning:

A proxy task succeeds while the target task-space degrades.

This is a concrete alignment failure mode: a system becomes a strong constructor of the wrong task family.

## Validation terms

### VAL0-CT

Public-facing phrase:

```text
the first Constructor-Theory task-space probe
```

Internal term:

```text
VAL0-CT
```

Plain meaning:

VAL0-CT is the first validation probe for proto-Omega. It tests whether future-bearing reachability can be detected in generated task algebras.

It does not validate full Omega.

### Constructor task algebra

Public-facing phrase:

```text
a simplified map of possible tasks and how they open or close future tasks
```

Internal term:

```text
constructor-style task algebra
```

Plain meaning:

A task algebra is a finite operational representation of Constructor-Theory-style possibility structure: tasks, constructors, enabling, obstruction, cost, reliability, and reachability.

Use this phrase carefully. VAL0 task algebras are Constructor-Theory-compatible operational models, not full physical derivations from fundamental laws.

### R0

Public-facing phrase:

```text
raw reachability
```

Internal term:

```text
R0
```

Plain meaning:

R0 asks what is reachable from the current task state within a horizon.

```text
R0:
  what can be reached?
```

### R1

Public-facing phrase:

```text
future-preserving reachability
```

Also useful:

```text
persistence-conditioned reachability
```

Internal term:

```text
R1
```

Plain meaning:

R1 asks what is reachable in a way that still leaves future reachability open.

```text
R1:
  what can be reached that still leaves futures open?
```

R1 is not Omega. It is a minimal proto-Omega predictor.

### Long-horizon reachability retention

Public-facing phrase:

```text
how much future reachability remains later
```

Internal term:

```text
LHR
```

Plain meaning:

LHR measures whether a task algebra still has reachable futures after a rollout.

In VAL0-CT, LHR is the primary outcome, not an Omega score.

### R0-lookahead

Public-facing phrase:

```text
equal-budget greedy reachability control
```

Internal term:

```text
R0-lookahead
```

Plain meaning:

R0-lookahead gets the same planning budget as R1 but greedily maximizes peak future reachability. It is a control for the possibility that R1 only wins because it looks farther ahead.

### Horizon sweep

Public-facing phrase:

```text
testing across short and longer futures
```

Internal term:

```text
horizon sweep
```

Plain meaning:

The probe tests multiple near-term, continuation, and held-out future horizons rather than tuning one timescale.

This matters because proto-Omega is temporal: a structure that looks good at a short horizon may collapse at a longer horizon.

## Failure-mode terms

### Fakeout

Public-facing phrase:

```text
misleading lower-level success
```

Internal term:

```text
fakeout
```

Plain meaning:

A fakeout occurs when a lower-level structure appears to satisfy a higher-level claim but does not carry the required structure.

A fakeout is not necessarily useless. It may be a valid lower-order component. It is only a fakeout relative to a claim level.

Example:

```text
a clock is valid as a clock
but a fakeout for recoverable historical identity
```

### Cheap factorization

Public-facing phrase:

```text
a simpler explanation that preserves the score but loses the target
```

Internal term:

```text
cheap factorization
```

Plain meaning:

Cheap factorization happens when an apparent success can be explained by a simpler mechanism that bypasses the structure we were trying to detect.

Examples:

```text
clock phase instead of identity
stasis instead of self-maintenance
noise distribution instead of structured branching
proxy task instead of target task
```

### Lock-in

Public-facing phrase:

```text
a future that preserves one path by closing others
```

Internal relation:

```text
pseudo-Omega / destructive lock-in
```

Plain meaning:

Lock-in is not merely stability. It is stability purchased by narrowing or closing future possibility.

### Noise branching

Public-facing phrase:

```text
many branches that do not carry structure forward
```

Internal term:

```text
noise branching
```

Plain meaning:

Noise branching gives many immediate variations but no stable downstream structure.

It is not lushness.

### Sterile branching

Public-facing phrase:

```text
branches that quickly terminate or converge
```

Internal term:

```text
sterile branching
```

Plain meaning:

Sterile branching produces distinguishable immediate futures that do not enable further meaningful differentiation.

## Constructor Theory terms used in Omega notes

### Task

Public-facing phrase:

```text
a possible transformation
```

Plain meaning:

A task specifies a transformation from one attribute to another.

In VAL0, tasks are simplified as graph nodes or transitions that can enable or obstruct other tasks.

### Constructor

Public-facing phrase:

```text
a system that can repeatedly perform or enable a task
```

Plain meaning:

A constructor is a task-capable system. In VAL0, constructors are simplified task-selecting mechanisms rather than full agents.

### Approximate constructor

Public-facing phrase:

```text
a bounded, imperfect task-capable system
```

Internal term:

```text
epsilon-constructor / approximate constructor
```

Plain meaning:

Real systems are not perfect constructors. They are noisy, bounded, degrading, and resource-constrained. VAL0 uses approximate constructors.

### Task repertoire

Public-facing phrase:

```text
the set of tasks still available
```

Internal term:

```text
task repertoire
```

Plain meaning:

A task repertoire is what a constructor or field can still do under current constraints.

### Enabling

Public-facing phrase:

```text
opening future tasks
```

Plain meaning:

A task enables another task when performing the first makes the second available.

### Obstruction

Public-facing phrase:

```text
closing future tasks
```

Plain meaning:

A task obstructs another task when performing the first makes the second unavailable or impossible under the current algebra.
