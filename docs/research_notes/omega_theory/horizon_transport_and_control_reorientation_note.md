# Horizon Transport and Control Reorientation Note

Status: theory-side reorientation after Stage B-2 spectral subspace/control sweeps  
Scope: RFS-MB0 spectral branch, gauge-shadow theory, and Omega-native future-field instrumentation  
Claim boundary: not a validation result, not Omega detection, not agent detection, not identity detection, not valuer detection

## 0. One-sentence version

The spectral branch should reorient from static co-occurrence-style future-field spectra toward horizon-transport spectra, and the control philosophy must separate detector null controls from candidate perturbation-response profiles.

In plainer terms:

```text
Omega is named for horizon.
The object should be measured by how futures transport across horizon,
not only by what signatures co-occur inside a horizon slice.

Null controls test the detector.
Perturbations test the candidate.
Do not confuse those two.
```

## 1. Why this note exists

The Stage B-2 spectral branch has produced useful negative/underdetermined results.

The current empirical pattern is:

```text
coflow/cofrontier spectra are mechanically constructible;
coflow spectral structure appears in direct-control smokes;
structure-destroying shuffle controls do not yet separate cleanly;
high-loading item ablation is random-equivalent;
subspace transfer signals have not beaten controls;
subspace distributedness currently reads diffuse/noise-like;
graph perturbation remains blocked.
```

This does not mean spectra are useless. It means the current spectral object may be wrong.

The likely failure modes are:

```text
1. statistic mismatch;
2. matrix-construction mismatch;
3. horizon or scale mismatch;
4. substrate resolution mismatch;
5. control philosophy drift.
```

This note highlights the fifth point because it has repeatedly reappeared in discussion: the project keeps drifting toward treating destructive ablations as ordinary negative evidence against candidate future-shaping structures. That is not the right standard for life-like, agency-like, or Omega-relevant objects.

## 2. What the language-space paper suggests, and what it does not

The hierarchical concept geometry paper provides a useful analogy.

Its setting is roughly:

```text
latent object:
  WordNet-like semantic hierarchy

observed relation:
  word co-occurrence

assumption:
  nearby concepts in the hierarchy co-occur more often

spectral result:
  normalized co-occurrence spectra recover coarse-to-fine hierarchy
```

That analogy is valuable, but Omega is not language taxonomy.

For Omega, the latent object is not a known static tree. The hypothesized object is a horizon-indexed future-shaping structure. If it is tree-like, it is likely tree-like in the sense of:

```text
coarse-to-fine branching of future continuations across horizon
```

not in the sense of a static class hierarchy.

Therefore the closest analogue to co-occurrence may not be:

```text
cofrontier:
  what signatures appear together at a horizon

coflow:
  what transition items co-occur inside a window
```

but rather:

```text
horizon transport:
  what future structures at H_a become, feed, open, close, or route into
  future structures at H_b
```

Omega is not an instant property. It is fundamentally a horizon object.

## 3. Proposed primary object: horizon transport

Define a horizon-transport object:

```text
T_{H_a -> H_b}
```

where rows represent structures visible at an earlier horizon and columns represent structures visible at a later horizon.

Candidate rows:

```text
frontier signatures at H_a;
source-side future-profile bins;
local flow-role signatures;
coarse reachable-region labels;
start-conditioned frontier summaries.
```

Candidate columns:

```text
frontier signatures at H_b;
downstream future-profile bins;
recovery / collapse / reopening labels if mechanically derived;
transport destination signatures;
later reachable-region labels.
```

Entries may represent:

```text
frequency;
transition mass;
conditional probability;
normalized transport residual;
control-relative excess transport;
transport survival under perturbation.
```

A spectral analysis of `T_{H_a -> H_b}` should normally use singular subspaces, because horizon transport is directional.

Primary spectral quantities:

```text
singular value spectrum;
left/right singular subspaces;
short-to-middle subspace alignment;
middle-to-downstream subspace alignment;
transport spectral gap;
transport concentration / participation;
transport entropy;
transport branch splitting;
transport collapse / reopening profile.
```

This is more Omega-native than static co-occurrence because it asks how future structure changes as horizon deepens.

## 4. Tree-like does not mean static

The live theory intuition is that the relevant object may be tree-like and horizon-dependent.

A tree-like horizon object might look like:

```text
short horizon:
  broad future route classes

middle horizon:
  route classes split into corridor, trap, recovery, collapse, or saturation families

downstream horizon:
  compatibility, re-entry, lock-in, or durable branching regimes appear
```

This is closer to a branching transport geometry than to a static taxonomy.

The spectral question becomes:

```text
Do the leading transport modes separate coarse future-continuation branches,
and do later modes refine them across horizon?
```

That is the Omega analogue of the language-space paper's coarse-to-fine spectral structure.

## 5. Critical control reorientation

This is the most important part of the note.

The project must stop collapsing two different questions:

```text
A. Does the detector distinguish observed structure from null/generated artifacts?

B. How does a candidate future-shaping structure respond to perturbation?
```

These are not the same.

### 5.1 Null controls test the detector

Null controls include:

```text
label shuffle;
context shuffle;
horizon shuffle;
frontier-size match;
probe-marginal match;
saturation timing match;
randomized fakeout systems.
```

Their purpose is to test whether the measurement procedure sees structure where it should not.

They answer:

```text
Is this spectral/metric pattern above a suitable null for the detector?
```

They do **not** answer:

```text
Would a living or life-like candidate survive injury?
```

A structure-destroying shuffle is supposed to be ablative. The issue is not that it changes the structure. The issue is whether the observed statistic separates from the structure-destroyed null in the expected direction.

### 5.2 Perturbations test the candidate

Perturbations include:

```text
small edge noise;
roughness changes;
asymmetry changes;
constraint jitters;
targeted channel disruption;
repair-path removal;
resource/cost changes;
recovery support changes;
lethal/destructive stress tests.
```

Their purpose is to measure the candidate's response profile.

They answer:

```text
How does the candidate deform, degrade, compensate, reroute, recover, or collapse?
```

They should not be reduced to:

```text
survived control = real;
failed control = fake.
```

### 5.3 Living systems are the guiding analogy

The hypothesized best real-world manifestations of Omega-relevant structure are living systems or life-like future-shaping systems.

Living systems do not survive arbitrary destructive ablation.

If one removes enough organs, randomizes enough channels, destroys enough metabolic regulation, or severs enough repair pathways, the organism dies. That does not mean life was fake. It means the perturbation crossed its viability boundary.

Therefore Omega-candidate controls should not be framed primarily as survival tests.

They should be framed as response-profile tests.

Expected response classes:

```text
non-lethal perturbation:
  compensation, small deformation, or preserved transport profile

functional perturbation:
  specific degradation, rerouting, or weakened transport branch

repair-enabled perturbation:
  recovery or re-entry

critical channel perturbation:
  collapse or loss of downstream transport

random irrelevant perturbation:
  weaker or less coherent effect than targeted perturbation

lethal/destructive perturbation:
  collapse, interpreted as boundary finding rather than falsification
```

## 6. Replace survival language with response geometry

The better question is not:

```text
Does the candidate survive ablation?
```

The better question is:

```text
What is the candidate's graded perturbation-response geometry?
```

A future-shaping candidate should be evaluated by:

```text
viability envelope:
  range of perturbations under which recognizable transport structure remains

degradation profile:
  how transport structure changes under increasing perturbation

specificity profile:
  targeted functional perturbations differ from matched random perturbations

repair profile:
  recovery or re-entry paths remain available under some disruptions

collapse profile:
  critical perturbations create predictable loss of transport/recoverability

horizon profile:
  short-horizon deformation, middle-horizon rerouting, downstream reopening or collapse
```

This is closer to biology and control theory than to a simple null-hypothesis survival test.

## 7. Proposed control taxonomy going forward

Future specs should explicitly separate the following.

### 7.1 Detector-null controls

Purpose:

```text
Do we see structure above null artifacts?
```

Examples:

```text
label/context/horizon shuffle;
frontier-size match;
probe-marginal match;
saturation timing match;
neutral/fakeout systems.
```

Interpretation:

```text
failure to separate blocks detector claims;
it does not, by itself, describe candidate viability.
```

### 7.2 Gauge/view controls

Purpose:

```text
Does the structure transform coherently across non-privileged views?
```

Examples:

```text
probe view;
flow mode view;
horizon band view;
scale/resolution view;
state-shape view;
coarse/fine signature view.
```

Interpretation:

```text
view dependence is not automatically failure;
unstructured view dependence is failure;
predictable view transformation is gauge coherence.
```

### 7.3 Non-lethal perturbations

Purpose:

```text
Measure response inside the viability envelope.
```

Examples:

```text
tiny edge roughening;
small parameter jitter;
minor constraint-weight change;
minor horizon perturbation;
small resolution perturbation.
```

Interpretation:

```text
expect deformation, not invariance.
```

### 7.4 Functional perturbations

Purpose:

```text
Test mechanism dependence and channel/recovery specificity.
```

Examples:

```text
target high-transport branch;
target suspected recovery route;
target bottleneck support;
target repair pathway;
target horizon-transport bridge mode.
```

Interpretation:

```text
specific degradation or rerouting supports functional dependence;
random-equivalent response weakens functional interpretation.
```

### 7.5 Lethal/destructive perturbations

Purpose:

```text
Find failure boundaries.
```

Examples:

```text
large random edge resampling;
strong constraint resampling;
heavy asymmetry flip;
removal of broad transition support;
collapse-inducing perturbation.
```

Interpretation:

```text
collapse under lethal perturbation is not evidence that the candidate was fake;
it marks the boundary of viability.
```

## 8. Horizon-transport response profiles

The next spectral object should track how transport changes under perturbation.

For each perturbation class, measure:

```text
T_{short -> middle}
T_{middle -> downstream}
left/right singular subspace alignment
transport spectral gap
transport entropy
transport participation
branch splitting / merging
collapse / reopening
control-relative residual transport
```

Response classes:

```text
transport_stable:
  transport subspace remains aligned under non-lethal perturbation

transport_rerouted:
  transport shifts to alternate branch without collapse

transport_weakened:
  branch or mode loses mass but structure remains interpretable

transport_reopens:
  local narrowing followed by downstream branching/recovery

transport_collapses:
  downstream structure collapses or saturates into trap/dead-end

transport_control_equivalent:
  null controls reproduce the transport profile

transport_resolution_mismatch:
  signal appears only under specific resolution/scale view
```

This should replace simple pass/fail survival language.

## 9. Implications for the recent sweep results

The recent sweep should not be read as:

```text
spectra are dead;
```

nor as:

```text
candidate failed destructive controls;
```

The better read is:

```text
static coflow/cofrontier spectra, as currently constructed, do not isolate a
future-field object above the current detector-null controls.

The item-local channel interpretation is not supported.

The distributed subspace interpretation is not yet above controls.

The next promising object is likely horizon-transport spectral geometry,
with controls split into detector nulls and candidate perturbation-response profiles.
```

## 11. 3P check

### Principled

Horizon transport follows directly from Omega's concern with future continuability across horizon.

### Parsimonious

It replaces multiple static co-occurrence-style matrices with a directional object:

```text
what future structures become across horizon
```

### Predictive

A valid horizon-transport object should predict downstream branch/recovery/collapse patterns and produce structured response profiles under perturbation.

If it does not predict, it should not be promoted.

## 12. Bottom line

The project should reorient from:

```text
static co-occurrence spectra + survival under ablation
```

to:

```text
horizon-transport spectra + detector null controls + graded perturbation-response geometry
```

This is both more faithful to Omega and more fair to life-like candidate structures.

The core principle going forward:

```text
Null controls test the detector.
Perturbations test the candidate.
Destructive ablation maps viability boundaries; it is not ordinary negative evidence.
```
