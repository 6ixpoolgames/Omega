# Presentation Fact Closure v0

Status: finite formal-context / Galois pilot
Scope: presentation/fact satisfaction, common facts, models of facts, closure operators
Claim boundary: not an admissibility criterion, not value, not agency, not identity, not Omega validation

## Purpose

The bridge problem is not just whether one presentation is sound. The larger
question is:

```text
given a declared family of admissible presentations,
which facts survive all of them?
```

This note records the first generic answer. We model presentations and facts
as two sides of a formal context:

```text
Presentation
Claim
Satisfies : Presentation -> Claim -> Prop
```

Then we derive:

```text
CommonClaims:
  claims satisfied by every presentation in a declared presentation set

ModelsOfClaims:
  presentations satisfying every claim in a declared claim set

PresentationClosure:
  presentations satisfying all claims common to a presentation set

ClaimClosure:
  claims common to all presentations satisfying a claim set
```

This is the standard Galois pattern behind formal concept analysis and
abstract-interpretation-style closure. The repo now has a small Lean surface
for it instead of relying on metaphor.

```text
TargetSatisfiesPresentation:
  a presentation satisfies a target when it preserves that target on fibers

PairVisibleSatisfiesPresentation:
  a presentation satisfies a pair when it keeps the pair visible

CommonTargets:
  targets preserved by every declared admissible presentation

CommonVisiblePairs:
  pairs kept visible by every declared admissible presentation
```

## Why This Matters

This is the first formal object that can carry the phrase:

```text
boundary-invariant fact under a declared admissible presentation family
```

without smuggling in identity or boundary realism. A fact is not declared
invariant because we like its interpretation. It is invariant only relative to:

```text
1. a declared presentation family;
2. a supplied satisfaction relation;
3. the common-fact closure generated by that relation.
```

That makes the next adversarial question precise:

```text
does the admissible family leave any nonconstant facts common,
or does it collapse everything useful?
```

## Relation To Recovery

The recovery layer now supplies many candidate facts:

```text
RecoveryExistsAt C target observe tau
RecoveryExistsInAt C target observe Allowed tau
RobustRecoveryAt Gamma target observe tau
ExpectedRecoveryExistsAt mu C target observe tau
HitProfile K target start
```

The closure layer does not yet turn these into one uniform fact type. It gives
the abstract surface where recovery, viability, carrier, and presentation facts
can be compared once a concrete satisfaction relation is supplied.

## Non-Claims

This note does not claim:

```text
that any particular presentation family is admissible;
that the admissible family is nontrivial;
that common facts exist beyond constants;
that common facts are value;
that common facts are agency;
that common facts are identity;
that this proves Omega.
```

## Next Work

The immediate next pilot should instantiate this layer on a small finite family:

```text
presentations:
  exact / coarse / stale / reflected views

facts:
  recovery, reachability, viability, and carrier-certification facts

tests:
  compute common facts;
  check whether nonconstant facts survive;
  adversarially add honest presentations to see whether the closure collapses.
```

That is the next step toward an admissibility criterion rather than a declared
admissibility label.
