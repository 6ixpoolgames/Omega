# Generated-Controller Robust Separation Protocol v0

Status:

```text
preregistration / finite exact controller-generation protocol
```

## Purpose

Test whether the retained strict separation

```text
joint May realization
+ pairwise Robust securability
does not imply
joint Robust securability
```

survives when policy/environment outcome rows are generated by finite-state
controller dynamics rather than inserted as a lookup table.

This is a controller-generation sprint. It is not a new compatibility
coordinate and it does not change the existing May or Robust quantifiers.

## Claim Boundary

This sprint may establish:

```text
finite exact May and Robust separation;
under a completely enumerated bounded deterministic controller class;
with one generated trajectory per controller/environment pair;
and candidate membership derived from trajectory facts.
```

It does not establish:

```text
the correct controller class;
the correct environment class;
partial-observation control in general;
stochastic or adversarial robustness;
empirical robustness;
identity;
agency;
valuerhood;
standing;
value;
moral compatibility;
or universal Omega.
```

## Fixed Quantifier Contract

For candidate family `G`, bounded controller class `C`, and nonempty
environment scope `E`:

```text
May(G):
  there exists a generated controller/environment trajectory realizing G.

Robust_E(G):
  there exists one controller c in C such that
  for every environment e in E,
  the generated trajectory run(c, e) realizes G.
```

Every Robust query in the strict comparison uses the same controller class,
environment scope, horizon, observation map, and candidate predicates.

## Fixed Controller Class

Use:

```text
actions:
  x, y, z

observations:
  tick

memory states:
  m0, m1

initial memory:
  m0

horizon:
  2
```

The observation map is constant over every world state. Controllers therefore
receive the same observation stream in both strict environments.

Enumerate every total deterministic controller with:

```text
update:
  Memory x Observation -> Memory

act:
  Memory x Observation -> Action
```

The declared class size is fixed before the run:

```text
2^(2 x 1) x 3^(2 x 1) = 36 controllers.
```

No controller may be added after seeing the result. The run must also retain
the induced two-action behavior classes. There should be nine action-sequence
classes; syntactically distinct controllers with the same generated sequence
must not be mistaken for independent behavioral evidence.

## Generated World Dynamics

Use two total deterministic controlled systems with the same:

```text
state interface;
action interface;
initial state;
observation map;
and horizon.
```

The first action contributes a base trajectory fact:

```text
x -> A
y -> B
z -> C
```

The second action contributes the same base fact. It may also contribute a
declared environment-specific order bonus:

```text
north:
  x then y also contributes C

south:
  y then x also contributes C
```

Candidate membership is read only from the terminal accumulated fact set:

```text
A is realized iff A is in the terminal fact set;
B is realized iff B is in the terminal fact set;
C is realized iff C is in the terminal fact set.
```

Candidate predicates must not inspect:

```text
controller identifiers;
environment identifiers;
witness identifiers;
or fixture labels.
```

## Preregistered Strict Cases

### Individual-environment realizability

Both strict environments must admit a generated triple:

```text
north:
  x then y realizes A, B, C

south:
  y then x realizes A, B, C
```

This prevents full-scope failure from being attributed to one environment
making the triple impossible under every controller.

### Pairwise Robust securability

Across the full scope `{north, south}`:

```text
x then y secures A, B;
x then z secures A, C;
y then z secures B, C.
```

Different controller rows may generate the same action sequence. Every
securing controller must be retained.

### Full-scope triple failure

The north triple requires sequence `x,y`; the south triple requires sequence
`y,x`. Because the observation stream is shared and constant, every declared
controller generates one common two-action sequence across both environments.

Expected:

```text
May({A,B,C}):
  true;

Robust_{north,south}({A,B,C}):
  false.
```

This expected result must be established by exhaustive controller enumeration,
not by checking a curated controller list.

### Scope sensitivity

Expected:

```text
Robust_{north}({A,B,C}):
  true;

Robust_{south}({A,B,C}):
  true;

Robust_{north,south}({A,B,C}):
  false.
```

May fibers and candidate classes must not change when only the selected Robust
environment scope changes.

## Matched Positive Control

Keep the controller class, observation map, horizon, candidate predicates, and
north environment fixed.

In the positive south environment, retain its original `y,x` order bonus and
also admit the north `x,y` order bonus.

Expected:

```text
Robust_{north,positive-south}({A,B,C}):
  true
```

through at least one controller generating `x,y`.

The strict and positive May candidate families must agree. The positive
fixture exists to show that the generated-run and Robust machinery can retain
a full-family controller when the dynamics permit one.

## Required Adapter

Add a reusable deterministic finite-state controller rollout that retains:

```text
world-state path;
selected action path;
observation path;
controller-memory path.
```

It must:

```text
validate the controller against the controlled system;
require point-mass selected transition rows;
retain horizon + 1 world and memory states;
and reject stochastic selected rows rather than silently sampling.
```

The generated `PolicyEnvironmentRuns` table must be reconstructed solely from
these retained trajectories.

The run must verify:

```text

```

## Acceptance Criteria

The sprint is retained only if:

1. The protocol is committed before implementation.
2. The implementation imports no historical Omega package.
3. The bounded controller class is completely enumerated.
4. Candidate incidence is derived from generated terminal trajectory facts.
5. Both strict environments individually admit a triple trajectory.
6. Every pair is Robust over the same full environment scope.
7. The full triple is May but not Robust over that scope.
8. Both singleton scopes restore Robust triple realization.
9. The matched positive fixture restores full-scope Robust triple realization.
10. Behavior quotienting changes no tested verdict.
11. All generated tables match fresh rollouts.
12. Focused and full Python validation pass.
13. Existing OmegaV2 and historical AlphaOmega Lean builds remain green.
14. No identity, agency, valuer, standing, value, or moral verdict is emitted.

## Kill Conditions

Stop for audit rather than retain the sprint if:

```text
the controller enumeration is partial;
the declared controller count is not 36;
the generated behavior-class count is not nine;
a candidate predicate inspects a fixture identifier;
a generated table row disagrees with fresh rollout;
the strict environments expose different observation streams;
either strict environment cannot realize the triple individually;
any pair is not Robust over the full scope;
the strict triple is Robust over the full scope;
either singleton scope fails to restore the triple;
the positive fixture fails to restore the full-scope triple;
behavior representative reduction changes a tested verdict;
pair and triple queries use different scopes;
May or Robust structural laws fail;
run evidence is discarded;
or the result is interpreted as identity, agency, valuerhood, standing, value,
moral compatibility, empirical robustness, or universal Omega.
```

## Public Compression

Two environments may each permit three trajectory facts together, while
requiring incompatible action orders to obtain them. A bounded controller that
receives the same observations in both environments can secure every pair
without any one controller securing the triple across both. This separates
joint realizability from joint robust securability using generated dynamics
and an exhaustively searched finite controller class.
